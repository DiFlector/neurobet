# Neurobet (Нейроставки)

## 1. Название проекта

**Neurobet** — исследовательский сервис для прогнозирования спортивных событий и симуляции ставок с использованием машинного обучения, локальной LLM и данных о матчах и коэффициентах Fonbet.

Основная идея проекта — не просто предсказывать исход матча, а построить полный замкнутый pipeline, в котором система:

1. получает актуальные данные о спортивных событиях и коэффициентах;
2. сохраняет изменения во времени;
3. формирует признаки для конкретного вида спорта;
4. ML-модель рассчитывает вероятности и ожидаемую ценность вариантов ставок;
5. локальная LLM дополнительно анализирует контекст, новости и внешние источники;
6. результаты ML и LLM объединяются в структурированный verdict;
7. отдельный `bet-manager` проверяет возможность ставки;
8. ставка записывается в виртуальный банкролл;
9. после окончания матча система определяет фактический результат;
10. вся история используется для анализа и последующего обучения моделей.

На первом этапе Neurobet работает **только в режиме виртуальных ставок (simulation/paper betting)**. Реальные денежные ставки не являются частью базового pipeline.

---

## 2. Главные принципы проекта

### Разделение ответственности

Каждый компонент должен выполнять одну понятную задачу. ML-модель не должна самостоятельно изменять баланс, LLM не должна самостоятельно ставить ставку, а frontend не должен содержать бизнес-логику расчёта ставок.

### Data-first подход

Любое решение должно быть воспроизводимым по сохранённым данным. Для важных сущностей и событий необходимо хранить timestamps и версии полученных данных.

### Спорт-независимое ядро

Ядро Neurobet должно работать одинаково для разных видов спорта. Специфика футбола, хоккея, тенниса, баскетбола и других дисциплин должна находиться в отдельных sport-модулях.

### ML важнее LLM

LLM является дополнительным источником информации и контекстного анализа. Она не должна заменять статистическую модель и не должна иметь право самостоятельно обходить ограничения `bet-manager`.

### Строгие контракты

Обмен между сервисами выполняется через явно определённые схемы данных. Все решения ML/LLM, передаваемые дальше в pipeline, должны быть структурированы и валидироваться.

### Сначала симуляция

Ставочный движок должен поддерживать виртуальный баланс, журнал операций, settlement и статистику. Архитектура должна позволять позднее добавить другой executor, не переписывая ML и LLM.

## 5. Основные сервисы Neurobet

### `collector`

Собирает данные Fonbet.

Основная задача — регулярно получать состояние матчей, линии, коэффициенты и результаты. Интервал между запросами должен быть случайным в диапазоне **5–10 секунд**, а timestamp каждого получения необходимо сохранять.

Collector не должен заниматься машинным обучением или принятием решения о ставке.

### `event-processor`

Приводит сырые данные к внутреннему формату Neurobet.

Он отвечает за:

- нормализацию событий;
- сопоставление сущностей;
- обновление состояния матча;
- определение изменений линии;
- подготовку данных для sport-specific pipeline.

### `neural`

Числовая ML-система.

Она рассчитывает вероятности исходов, confidence, потенциальный value/edge и другие метрики, необходимые для принятия решения.

Модель должна обучаться на исторических данных и проходить backtesting.

### `llm`

Локальная LLM, запускаемая на пользовательском сервере.

Предполагается использование небольшой модели, способной работать в условиях ограниченных GPU-ресурсов, включая NVIDIA GTX 1050 Ti.

LLM не является главным предиктором. Она получает структурированный контекст и возвращает строго определённый JSON.

### `research`

Отдельный контур внешнего информационного поиска.

Он собирает найденные материалы о матчах, командах, игроках, травмах, составах, форме и других факторах, которые могут дополнить числовую модель.

Важны:

- URL источника;
- время публикации;
- время получения;
- источник;
- краткое содержание;
- оценка свежести;
- связь материала с конкретным матчем или участником.

### `bet-manager`

Центральный контроллер виртуальных ставок.

Он является единственным компонентом, который может зарегистрировать ставку в системе.

Перед созданием ставки он обязан проверить как минимум:

- существует ли матч;
- актуальна ли линия;
- не завершён ли матч;
- соответствует ли ставка доступным рынкам;
- достаточно ли виртуального баланса;
- не превышены ли лимиты риска;
- не существует ли дубликат ставки;
- не устарел ли ML/LLM verdict;
- соответствуют ли данные ожидаемой версии схемы.

ML и LLM могут только **рекомендовать** ставку. `bet-manager` принимает итоговое техническое решение о том, может ли она быть зарегистрирована.

### `backend`

Предоставляет API для frontend и внешних внутренних компонентов.

Не должен дублировать ML-логику.

### `frontend`

Web-интерфейс Neurobet.

Через него необходимо видеть:

- текущие и завершённые матчи;
- коэффициенты и их изменения;
- прогнозы ML;
- verdict LLM;
- решения `bet-manager`;
- виртуальный баланс;
- открытые ставки;
- закрытые ставки;
- PnL;
- ROI;
- статистику моделей;
- историю экспериментов.

## 6. Работа с несколькими видами спорта

Нельзя писать футбольную логику непосредственно в общем ядре, если она не является универсальной.

Каждый спорт должен иметь собственный adapter/module, например:

```text
sports/
├── common/
├── football/
├── basketball/
├── hockey/
└── tennis/
```

У каждого спорта могут существовать собственные:

- entities;
- события матча;
- игровые состояния;
- features;
- модели;
- market mappings;
- правила settlement;
- preprocessing;
- evaluation metrics.

При этом общие инфраструктурные компоненты должны оставаться едиными.

## 7. База данных

История — одна из центральных частей Neurobet.

Необходимо сохранять не только итоговый счёт, но и временное развитие матча и линии.

Как минимум должны существовать сущности для:

- sports;
- competitions;
- teams;
- players;
- matches;
- match participants;
- match state snapshots;
- odds/market snapshots;
- model predictions;
- LLM verdicts;
- research documents;
- bet requests;
- accepted bets;
- rejected bets;
- settlements;
- bankroll transactions;
- model versions;
- experiments;
- training datasets.

Для временных данных timestamps должны быть обязательны там, где это необходимо для восстановления состояния системы в прошлом.

Особенно важно не допускать data leakage при обучении: модель должна использовать только информацию, которая была доступна системе на соответствующий момент времени.

## 9. Правила для AI coding agent

При работе с Neurobet агент должен сначала читать:

```text
AGENTS.md
01-ARCHITECTURE.md
02-ROADMAP.md
```

Перед крупным архитектурным изменением необходимо проверить, не противоречит ли оно `01-ARCHITECTURE.md`.

При реализации новых возможностей необходимо определить соответствующее место в `02-ROADMAP.md`.

После реализации значимого архитектурного решения документация должна быть обновлена.

Нельзя:

- смешивать frontend, backend, ML и betting business logic в одном сервисе;
- позволять LLM напрямую изменять bankroll;
- позволять LLM напрямую регистрировать ставки;
- обходить проверки `bet-manager`;
- обучать модель на информации, которая появилась после момента принятия решения;
- удалять исторические snapshots ради экономии места без специальной политики retention;
- завязывать общее ядро на один вид спорта;
- хранить критические verdicts только в логах;
- использовать неструктурированный текст между критическими сервисами вместо версионируемых JSON-схем.

## 10. Критическая цепочка принятия решения

Основная логика Neurobet должна выглядеть концептуально так:

```text
Fonbet
   ↓
collector
   ↓
raw snapshots
   ↓
event-processor
   ↓
normalized match state
   ↓
┌──────────────────────┐
│                      │
↓                      ↓
neural               research
│                      │
│                  local LLM
│                      │
└──────────┬───────────┘
           ↓
      combined verdict
           ↓
      bet-manager
           ↓
    validation + risk
           ↓
    virtual bankroll
           ↓
       settlement
           ↓
       statistics
           ↓
   training / backtesting
```

Это центральный pipeline проекта.

## 11. Что является конечной целью Neurobet

Цель проекта — построить систему, которая способна на исторических данных и в режиме реального времени оценивать качество собственных прогнозов, симулировать ставки, измерять прибыльность стратегий и постепенно улучшать модели.

Главным результатом считается не количество сделанных прогнозов, а качество проверяемого эксперимента:

```text
prediction → decision → simulated bet → outcome → evaluation → learning
```

Neurobet должна позволять сравнивать различные стратегии, версии моделей и варианты использования LLM на одной исторической базе данных и в едином формате экспериментов.

## 12. Интеграция с Model Context Protocol (MCP)

В репозитории реализован полнофункциональный **MCP-сервер** (`packages/mcp-server`), предназначенный для взаимодействия AI-агентов (в таких IDE, как **Cursor** и **Antigravity**) с платформой Neurobet.

### Конфигурация подключения:

Конфигурации хранятся в `.cursor/mcp.json`, `.agents/mcp_config.json` и глобальном `~/.gemini/config/mcp_config.json`:

```json
{
  "mcpServers": {
    "neurobet": {
      "command": "python3",
      "args": [
        "-u",
        "/srv/neurobet/packages/mcp-server/src/neurobet_mcp/server.py"
      ],
      "env": {
        "NEUROBET_API_URL": "https://necrolich.ru/diflector/neurobet",
        "PYTHONPATH": "/srv/neurobet/packages/mcp-server/src"
      }
    }
  }
}
```

> **Важно:** Все запросы (включая метрики и таргеты Prometheus) идут через единую точку входа `NEUROBET_API_URL` благодаря встроенному backend-прокси (`/api/prometheus/query`, `/api/prometheus/targets`). Никаких локальных портов наружу не выставляется.

### Доступные группы инструментов MCP:

1. **Здоровье кластера и мониторинг**:
   - `neurobet_get_system_health`: агрегированный статус БД, Redis, планировщика, банкролла и активных моделей.
   - `neurobet_query_prometheus`: выполнение любых PromQL-запросов к временным рядам.
   - `neurobet_get_prometheus_targets`: проверка состояния всех 5 таргетов сбора метрик.
2. **Управление ML-моделями и Shadow Mode**:
   - `neurobet_list_models`, `neurobet_get_active_model`.
   - `neurobet_get_shadow_report`, `neurobet_register_shadow_model`, `neurobet_promote_model`, `neurobet_rollback_model`.
   - `neurobet_simulate_inference`: безопасная песочница симуляции инференса без сайд-эффектов.
3. **Тренировки и Эксперименты**:
   - `neurobet_trigger_training`, `neurobet_list_training_runs`.
   - `neurobet_list_experiments`, `neurobet_compare_experiments`.
4. **События линии Fonbet и Web Research**:
   - `neurobet_list_live_events`, `neurobet_get_event_timeline`, `neurobet_get_event_odds`.
   - `neurobet_get_predictions`, `neurobet_get_research_packet`.
5. **Виртуальный банкролл и ставки**:
   - `neurobet_get_bankroll_summary`: баланс, equity, заблокированная маржа, PnL, ROI.
   - `neurobet_list_virtual_bets`, `neurobet_list_bet_proposals`, `neurobet_sync_settlements`.
