# Промпт для регулярного ревью нейросети (скопировать и вставить в Claude Code вместе с выгрузками)

---

Проект NeuroBet, сервис ставок с нейросетью в `ai_service/app/neuralbet/` (GRU + LightGBM + рыночная вероятность в смеси, калибровка по спорту×децилю×кэфу, decision-порог, quarter-Kelly, кап кэфа для ставок).

Проведи ревью работы нейросети и скажи, что улучшить/изменить.

**Данные бери отсюда (открытый API, без авторизации — ничего выгружать вручную не нужно):**
`GET <домен>/api/ai/overview` — один запрос, отдаёт всё сразу: db_stats, bet_type_stats
(guess-rate по спорту/типу ставки), roi_stats (ROI и Brier по диапазонам кэфа —
то же самое, что раньше смотрели на странице «Статистика»), bankroll, ai_settings,
training_health (индикатор переобучения), backtest_history (последние прогоны бэктеста)
и recent_ai_logs. Параметры: `bet_types_limit` (по умолчанию 5 — сколько типов ставок на
спорт, 0 = только итоги по спорту), `logs_limit` (по умолчанию 60), `backtest_runs`
(по умолчанию 10). Если домен ещё не сказан — спроси его первым делом, дальше сам
дёргай ссылку по мере необходимости (после новых правок, раз в день-два и т.д.), не жди
каждый раз ручной выгрузки.

Если что-то не покрыто /api/ai/overview (сырые логи за произвольный период, полная
разбивка по всем типам ставок без обрезки) — можно попросить также:
- логи админки (TRAINING/INFERENCE/BANKROLL) текстом
- JSON конкретного бэктеста из кнопки «Бэктест» в админке

**Что проверить по логам:**
1. `best_epoch` в проходах обучения — систематически ли ≤2 на батчах, прошедших `MIN_TRAIN_SAMPLES` (признак заучивания батча). Сравни с порогом и предложи новое значение `NEURALBET_MIN_TRAIN_SAMPLES`, если нужно.
2. Стабильность тюнера: как ходят `blend_weight` / `market_weight` / `decision_threshold` между строками «Ensemble tuned» — сгладились ли скачки, куда сходятся веса. Если `market_weight` уехал к 1.0 — модель не добавляет сигнала, скажи об этом прямо.
3. Строка «val Brier ... vs market-only ... (model beats market / market beats model)» — какая доля циклов за выгрузку в пользу модели.
4. Число вердиктов «выиграет» между соседними циклами инференса — перестало ли скакать в разы.
5. Частота «Skipping training step — only N samples» — не простаивает ли обучение слишком часто (тогда порог/частоту надо крутить в другую сторону).

**Что проверить по бэктесту (главное):**
6. `overall.current` vs `overall.market_brier` — бьёт ли текущая модель рынок по Brier. Это ключевой вопрос «есть ли edge вообще».
7. ROI текущей модели по диапазонам кэфа (`by_coefficient`) — сравни с прошлыми запусками из истории; особенно диапазон 1.0–2.0 (там модель ближе всего к рынку) и работает ли кап `MAX_BET_COEFF`.
8. `current` vs `historical` — стала ли текущая версия модели лучше той, что предсказывала раньше.
9. Тренд по `history`: ROI/точность/Brier от запуска к запуску — растёт, стоит, падает.

**Формат ответа:**
- Сначала вердикт одним абзацем: модель улучшается / стоит на месте / деградирует, и есть ли edge против рынка.
- Потом конкретика по пунктам выше — только те, где есть находка, без воды.
- В конце — приоритизированный список правок (если нужны) с указанием файлов/констант; мелкие правки можешь сразу внести, спорные — сначала предложи.
- Будь честным: если данные говорят, что edge нет и не появляется, скажи это прямо, а не предлагай бесконечный тюнинг.

**Контекст прошлых решений (чтобы не предлагать заново то, что уже сделано):** пол вероятности 12% убран (теперь 1/99), cost-вес decision-лосса капнут (max 3.0), рыночная вероятность добавлена в смесь (`market_weight`, тюнится по Brier), калибровка учитывает диапазон кэфа, тюнер сглажен (EMA 0.3, порог ≥80 val-ставок, штраф за малую выборку), обучение реже (`TRAIN_EVERY_CYCLES=3`, `MIN_TRAIN_SAMPLES=1000`, батч 5000, val-срез 1000), LR дообучения 1e-4 (и принудительно переустанавливается после загрузки чекпоинта), тюнинг раз в `TUNE_EVERY_CYCLES=5`, есть бэктест в админке, индикатор переобучения (стрик best_epoch≤2 ×3 + тренд бэктеста), кнопка «Обнулить нейросеть» (сброс весов + trained_count без удаления архива). Гейты ставок: `MAX_BET_COEFF=2.0` (диапазон 2.0–3.0 давал −23% ROI), минимальный EV `MIN_BET_EDGE_PCT=3%` по калиброванной вероятности, минимальная поддержка рынка `MIN_MARKET_SUPPORT=150` решённых исходов в архиве (редкие рынки не убраны из обучения — только из ставок), пол кандидатов порога поднят до 0.40. Те же три гейта (через общие env-переменные `NEURALBET_*`) продублированы в backend/database.py и применены к списку «Активные LIVE прогнозы»/«Нейроставки AI TOP» (`get_top_neurobets`): кап кэфа и мин. EV — только для verdict="win", фильтр поддержки рынка — всегда; список теперь совпадает с тем, во что бот реально ставит. Правило «максимум одна открытая ставка на матч» действует везде (реальные ставки, витрина, обучающий bankroll-лосс, бэктест). Кап понижен до `MAX_BET_COEFF=2.0`. Бэктест из админки гоняет 40k сэмплов (15k стали покрывать <1 часа при текущем объёме архива); health-сигнал C (ROI не растёт) молчит, пока в каждом запуске окна меньше 100 ставок (`TRAINING_HEALTH_MIN_ROI_BETS`) — ROI на ~30 ставках это шум. Метрика accuracy бэктеста при жёстких гейтах отражает базовые частоты (модель почти всем говорит «не ставить»), смотреть надо на Brier vs market и на ROI при достаточном числе ставок. Бэктест теперь также запускается автоматически 4 раза в день (00:00/06:00/12:00/18:00 МСК, планировщик в ai_service/main.py, вызов run_backtest() в процессе, без HTTP) и целиком под pipeline._engine_lock — обучение и бэктест больше не могут выполняться параллельно, только по очереди. В админке есть блок-график `QualityTrendChart` (ROI/точность/Brier vs рынок/число ставок по прогонам бэктеста) и `TrainingTrendChart` (val_loss/val_guess_rate по проходам обучения, из нового файла `training_runs.json` — раньше эти числа существовали только как текст в логах и нигде не сохранялись). Индикатор переобучения теперь на 4 сигналах (добавлен D: val_loss_trending_up — среднее по свежей половине последних `TRAINING_HEALTH_VAL_LOSS_WINDOW=10` проходов выше среднего по старой половине), статус danger — большинство (3 из 4). Тюнинг/батчи ускорены под выросший архив (500k+ строк): `TRAIN_BATCH_TOTAL=10000`, `TRAIN_EVERY_CYCLES=20`, `MIN_TRAIN_SAMPLES=2000`, `VAL_BATCH_LIMIT=2000`, `BATCH_SIZE=256`, `LGB_TRAIN_LIMIT=40000`, `LGB_REFIT_EVERY_CYCLES=20`, `TUNE_EVERY_CYCLES=10` — все вынесены в `.env`/`.env.example` (`NEURALBET_*`). `decision_threshold` теперь тюнится не только глобально, но и **отдельно по видам спорта** (`NeuralBetEnsemble.sport_decision_thresholds`, `tune_ensemble`'s per-sport sweep, `_MIN_THRESHOLD_BETS_PER_SPORT=50`) — сорт с достаточной val-выборкой (обычно только настольный теннис/баскетбол) получает свой порог, остальные молча используют глобальный `decision_threshold`. Полная замена модели на спорт **отклонена** осознанно — данные слишком перекошены (2 спорта = ~52% архива), отдельная сеть уморит голодом редкие виды спорта; per-sport порог поверх общей модели даёт большую часть выгоды без этого риска. Потребители порога (`pipeline.py` инференс, `backtest.py` current_pred) синхронно читают через `ensemble_engine.sport_threshold(sport)` — если увидишь расхождение между live-вердиктами и бэктестом по конкретному спорту, проверь именно эту точку в первую очередь.
