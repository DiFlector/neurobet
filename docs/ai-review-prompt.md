# Промпт для регулярного ревью нейросети (скопировать и вставить в Claude Code вместе с выгрузками)

---

Проект NeuroBet, сервис ставок с нейросетью в `ai_service/app/neuralbet/` (GRU + LightGBM + рыночная вероятность в смеси, калибровка по спорту×децилю×кэфу, decision-порог, quarter-Kelly, кап кэфа для ставок).

Проведи ревью работы нейросети и скажи, что улучшить/изменить.

**Данные бери отсюда (открытый API, без авторизации — ничего выгружать вручную не нужно):**
`GET <домен>/api/ai/overview` — один запрос, отдаёт всё сразу: db_stats, bet_type_stats
(guess-rate по спорту/типу ставки), roi_stats (ROI и Brier по диапазонам кэфа —
то же самое, что раньше смотрели на странице «Статистика»), bankroll, ai_settings,
training_health (индикатор переобучения), backtest_history (последние прогоны бэктеста)
и recent_ai_logs. Параметры: `bet_types_limit` (по умолчанию 5 — сколько типов ставок на
спорт, 0 = только итоги по спорту), `logs_limit` (по умолчанию 60), `backtest_runs`
(по умолчанию 10). Если домен ещё не сказан — спроси его первым делом, дальше сам
дёргай ссылку по мере необходимости (после новых правок, раз в день-два и т.д.), не жди
каждый раз ручной выгрузки.

Если что-то не покрыто /api/ai/overview (сырые логи за произвольный период, полная
разбивка по всем типам ставок без обрезки) — можно попросить также:
- логи админки (TRAINING/INFERENCE/BANKROLL) текстом
- JSON конкретного бэктеста из кнопки «Бэктест» в админке

**Что проверить по логам:**
1. `best_epoch` в проходах обучения — систематически ли ≤2 на батчах, прошедших `MIN_TRAIN_SAMPLES` (признак заучивания батча). Сравни с порогом и предложи новое значение `NEURALBET_MIN_TRAIN_SAMPLES`, если нужно.
2. Стабильность тюнера: как ходят `blend_weight` / `market_weight` / `decision_threshold` между строками «Ensemble tuned» — сгладились ли скачки, куда сходятся веса. Если `market_weight` уехал к 1.0 — модель не добавляет сигнала, скажи об этом прямо.
3. Строка «val Brier ... vs market-only ... (model beats market / market beats model)» — какая доля циклов за выгрузку в пользу модели.
4. Число вердиктов «выиграет» между соседними циклами инференса — перестало ли скакать в разы.
5. Частота «Skipping training step — only N samples» — не простаивает ли обучение слишком часто (тогда порог/частоту надо крутить в другую сторону).

**Что проверить по бэктесту (главное):**
6. `overall.current` vs `overall.market_brier` — бьёт ли текущая модель рынок по Brier. Это ключевой вопрос «есть ли edge вообще».
7. ROI текущей модели по диапазонам кэфа (`by_coefficient`) — сравни с прошлыми запусками из истории; особенно диапазон 1.0–2.0 (там модель ближе всего к рынку) и работает ли кап `MAX_BET_COEFF`.
8. `current` vs `historical` — стала ли текущая версия модели лучше той, что предсказывала раньше.
9. Тренд по `history`: ROI/точность/Brier от запуска к запуску — растёт, стоит, падает.

**Формат ответа:**
- Сначала вердикт одним абзацем: модель улучшается / стоит на месте / деградирует, и есть ли edge против рынка.
- Потом конкретика по пунктам выше — только те, где есть находка, без воды.
- В конце — приоритизированный список правок (если нужны) с указанием файлов/констант; мелкие правки можешь сразу внести, спорные — сначала предложи.
- Будь честным: если данные говорят, что edge нет и не появляется, скажи это прямо, а не предлагай бесконечный тюнинг.

**Контекст прошлых решений (чтобы не предлагать заново то, что уже сделано):** пол вероятности 12% убран (теперь 1/99), cost-вес decision-лосса капнут (max 3.0), рыночная вероятность добавлена в смесь (`market_weight`, тюнится по Brier), калибровка учитывает диапазон кэфа, ставки капнуты `MAX_BET_COEFF=3.0`, тюнер сглажен (EMA 0.3, порог ≥80 val-ставок, штраф за малую выборку), обучение реже (`TRAIN_EVERY_CYCLES=3`, `MIN_TRAIN_SAMPLES=500`), тюнинг раз в `TUNE_EVERY_CYCLES=5`, есть бэктест в админке, индикатор переобучения (стрик best_epoch≤2 ×3 + тренд бэктеста), кнопка «Обнулить нейросеть» (сброс весов + trained_count без удаления архива).
