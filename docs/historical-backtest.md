# Исторический бэктест зарегистрированных моделей

Этот прогон повторяет live inference на последних завершённых матчах. Модель берётся из реестра как готовый checkpoint. Walk-forward команда `make backtest` здесь не используется: она заново обучает модель на фолдах.

Прогон не создаёт строки в `bets`, `ledger_entries`, `ml_predictions` и не меняет боевой виртуальный баланс.

## Что именно повторяется

- Полная лента состояния и коэффициентов, без сжатия до 12 точек. Если матч уже лежит в обучающей ленте той же версии признаков, готовые строки признаков читаются оттуда, а заново не строятся. Коэффициенты для исполнения всё равно читаются из таблицы котировок. Матчи, которых в ленте ещё нет, считаются по сырым снимкам.
- Для `tennis_v4` discriminator `market_is_set` при replay восстанавливается из выбранной головы: `0` для матча и `1` для котируемого сета. Цены исполнения берутся из соответствующего рынка на момент среза; матчевые цены не подставляются в сетовую ставку. Это также применяется к старым кэшированным строкам, записанным до появления признака.
- Результаты исторического replay не попадают в live-журнал модели. Поэтому нулевые показатели SHADOW означают, что live-подтверждений ещё нет, даже если отдельный backtest уже содержит исторические ставки.
- Признаки и история игроков ограничиваются моментом среза: `observed_at <= decision_timestamp`.
- Research и LLM берутся из уже сохранённых verdicts, созданных не позже среза. Если записи нет, контекст нейтральный. Новые запросы к research и LLM не отправляются.
- Сторона фиксируется по числу последовательных подтверждений из политики спорта и модели; универсального значения по умолчанию нет. Для тенниса `v2`, v4 и составной модели дополнительно поддерживаются котируемые сеты и вердикт матча. Закрытые сеты берутся из снимка на этот срез, как в лайве. Итоговый `set_winners` матча используется только после ставки, чтобы поставить победу, поражение или возврат.
- Исполнение учитывает задержку, свежесть линии и проскальзывание. Окно коэффициентов по умолчанию совпадает с live `stake_gate`; режим `range` заменяет его на явные границы.
- Каждая принятая сторона стоит фиксированную сумму. По умолчанию баланс `5000`, ставка `100`, порог банкротства `100`. Когда доступный баланс становится ниже порога, счётчик банкротств увеличивается на 1, баланс возвращается к начальному, и следующие матчи продолжают считаться.
- В выборку входят только `ACTIVE` и `SHADOW`. `RETIRED` и тестовый тег `test_` не участвуют.

`ROI = прибыль / оборот`. Возвраты не входят в процент побед. Банкротства не считаются прибылью: они только пополняют бумажный баланс, чтобы модель могла продолжить.

## Админка

Сейчас исторический прогон доступен только для тенниса. Открой «Админка» → «Бэктест». Выбери одну теннисную модель или все боевые и теневые модели тенниса, отметь рынки и запусти прогон. «Победа в матче» доступна всем теннисным моделям. «Победа в сете» доступна v2, v4 и составной модели; у остальных этот рынок пропускается. В таблице строка «Всего» — общий бумажный баланс, а строки «Матч» и «Сет N» — ставки, победы и ROI только этого рынка. Таблица показывает ставки, победы, процент побед, ROI, итоговый баланс, просадку и банкротства. «Копировать JSON» кладёт в буфер полный отчёт: запрос, версии, ставки и причины отклонений.

История стоит под таблицей и хранит не больше 25 прогонов. Новый запуск при заполненном списке удаляет самый старый завершённый прогон; идущий прогон не удаляется. «Открыть» показывает сохранённый отчёт и подставляет его параметры в форму. «Ещё раз» ставит в очередь новый прогон с тем же запросом: для всего вида спорта берутся текущие `ACTIVE` и `SHADOW`, а не модели из старого отчёта. «Удалить» убирает прогон и бумажные результаты. Боевые ставки при этом не меняются.

## MCP

Сначала посмотри реестр через `neurobet_list_models` и возьми `id` нужной `ACTIVE` или `SHADOW` модели.

Запуск одной модели:

```json
{
  "scope": "model",
  "sport_code": "tennis",
  "model_version_id": "<uuid из реестра>",
  "match_limit": 100,
  "initial_bankroll": 5000,
  "fixed_stake": 100,
  "bankruptcy_threshold": 100
}
```

Инструмент: `neurobet_trigger_backtest`. Для всех боевых и теневых моделей спорта укажи `"scope": "sport"` и не передавай `model_version_id`.

Ответ содержит `id` и статус `queued`. Пока статус `queued` или `running`, читай `neurobet_get_backtest_run` с этим `run_id`. Готовый отчёт лежит в `results`: у каждой модели свои `bets`, `wins`, `win_rate`, `roi`, `final_balance`, `bankruptcies` и `bet_records`.

`neurobet_list_backtest_runs` показывает последние запуски без списка ставок. Повтор того же запроса, пока предыдущий ещё выполняется, возвращает уже существующий запуск и не создаёт второй.

`match_limit` выбирает число последних доступных матчей. Для воспроизводимого прогона передай `event_ids`; этот список имеет приоритет над `match_limit` и записывается в запрос.

Если gate-поля не переданы, теннисный replay наследует их из `sports/tennis/tennis.cfg`. Общие overrides `min_edge`, `min_probability`, `confirmations`, `odds_gate_mode`, `min_odds` и `max_odds` применяются к матчу и сету. Поля конкретного рынка (`match_min_edge`, `set_min_edge`, соответствующие `*_min_probability`, `*_confirmations`, `*_gate_mode` и границы odds) имеют приоритет только для своего рынка. В отчёте сохраняются фактически разрешённая политика и её SHA-256.

Остальные параметры исполнения: `max_odds_staleness_sec`, `execution_latency_sec`, `allow_slippage`, `initial_bankroll`, `fixed_stake` и `bankruptcy_threshold`.
