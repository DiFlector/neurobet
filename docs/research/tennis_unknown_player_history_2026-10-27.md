# Неизвестная история игрока: PIT v2

По указанию пользователя отсутствие истории, недоступный источник и неподтверждённая identity обрабатываются как новый игрок. Политика `unknown_player_history_v1` задаёт для соответствующей стороны Elo 1500, форму 0.5, 0 матчей и `player_metrics_missing=1`. Разности признаков пересчитываются после замены. Это обозначает отсутствие известных системе данных, а не подтверждение реального дебюта игрока.

Общее разрешение входов используется builder, historical audit и live forecast. Непроверяемые или поздние player metrics заменяются стартовыми значениями; статистика второй стороны с пригодными доказательствами сохраняется. Причина замены и отвергнутое source evidence сохраняются в артефакте builder. Запись `observation_kind=contract_prior` не является наблюдавшейся историей; её время обозначает причинный расчёт фиксированной константы для среза. Исторические source timestamps и identity решения не меняются. V1 сохраняет прежнюю обработку. Порядок и размер вектора v2 не меняются.

## Повторная проверка сохранённого входа

Strict builder повторно обработал тот же provenance JSONL `tennis_training_examples_10df6b1408b3.jsonl` (7,792 примера), без нового чтения всей production БД. Новый builder: `tennis_odds_free_dataset_v2_unknown_players_v1`.

- Стартовые значения применены в 6,655 примерах: сторона A — 6,331, сторона B — 6,289. Числа пересекаются.
- Отказов по player metrics больше нет.
- Принято 5/7,792, остальные 7,787 всё ещё отклонены.
- Нет serve evidence: сторона A — 7,772, сторона B — 7,779.
- У 50 примеров отсутствуют обязательные поля состояния.
- У 283 меток неизвестно время получения; ограничение их использования в исторических train-окнах сохраняется.

Подача остаётся независимым источником: новый режим игрока не создаёт фиктивные сыгранные очки. Внешние identity не подтверждаются автоматически, имена не объединяются. Обучение не запускалось.
