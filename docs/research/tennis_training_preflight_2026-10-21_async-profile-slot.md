## Текущий безопасный census, 16:06 UTC

Лёгкие SQL-счётчики после прерванного полного аудита показали: 635 PBP documents и parsed versions, 59 внешних матчей, 67 событий Fonbet с подтверждённой связью, 3 152 числовых Fonbet tennis events. Они не пересчитывают уникальные подтверждённые метки и окна; до следующего полного аудита нельзя утверждать, что label counts/manifest не изменились. Числа `635/59/67/3152` — только census, не sample-size admission.

Полный аудит в 16:02 UTC был остановлен до завершения, когда память `neurobet_postgres` достигла около 1.999 GiB из лимита 2 GiB. PostgreSQL и API оставались healthy. Следующая попытка должна сначала уменьшить нагрузку аудита: читать большие версии PBP пакетами/потоком вместо одновременного `.all()` всего набора, не создавать отдельные огромные списки содержимого JSON и контролировать память БД. До этого использовать сохранённый полный отчёт с явной пометкой о его времени, не заменять PIT-времена временем матча или расписанием.

## Блокеры перед обучением

1. Увеличить подтверждённую point/game/set историю до неизменённых минимумов 500 / 100 на каждое validation окно / 200 holdout; не засчитывать повторные документы и неоднозначные связи.
2. Получить реально observed PBP и сохранить достаточное число состояний до соответствующих исходов. Ретроспективный архив остаётся полезен для labels, но не подменяет live features.
3. Не считать ретроспективно полученные match results доступными в прошлой точке. Для старых окон нужны оригинальные timestamps доказанного получения; иначе матчи исключаются из chronology.
4. Утвердить и версионировать закрытый odds-free feature list совместно с inference/replay. Contract defaults должны оставаться явными; неподтверждённые Glicko/H2H/serve/surface не добавлять без собственной PIT-проверки.
5. Оптимизировать полный audit для рабочей БД и только после успешного сохранения повторить единый manifest. Для этого рабочего набора в manifest не запускать fit, tuning или calibration.
