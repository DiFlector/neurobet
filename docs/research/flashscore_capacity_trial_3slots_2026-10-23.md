# Flashscore: сравнение двух и трёх слотов — 2026-10-23

## Решение

Испытание завершено по 30 минут на каждую конфигурацию. Штатно оставлено **2 browser slots**: три слота дали заметный прирост профильных результатов и продвижение архива, но p95 ожидания live PBP вырос выше установленного порога. Условие сохранения трёх слотов не выполнено.

## Измерения

| Метрика за 30 минут | 2 слота, baseline | 3 слота, trial |
|---|---:|---:|
| Срезы каждые ~15 секунд | 103 | 102 |
| Успешно обновлённые профили по БД | 11 | 20 (+82%) |
| Новые подтверждённые Flashscore identity links | 7 | 18 (+157%) |
| Успешные поиски матча | 0 | 1 (новое событие; фиксированные ID: 0 в обоих окнах) |
| PBP-документы, полученные за окно | 33 | 33 |
| Завершённые задания полного архива | 0 | 4 |
| p95 ожидания live PBP | 13 с | 63 с (+385%) |
| p95 задержки queue API | 0.237 с | 0.263 с |
| Worker CPU p95 / максимум | 149% / 155% | 201% / 206% |
| Worker memory максимум | 1,746 MiB из 2 GiB | 1,908 MiB из 3 GiB |
| Одновременно наблюдавшиеся Chromium root процессы | 2 | 3 |
| Срезы с `overdue_pbp > 0` | 8/103 | 14/102 |

Профильные результаты включают новые поступления за время окна и подтверждены через `TennisPlayerProfile.last_success_at`; повторы с ошибкой в успехи не включались. Всего подтверждённых новых identity links выросло с 7 до 18. В фиксированной когорте успешно обновились 2 профиля в каждом окне; у сопоставлявшихся между окнами участников набор не полностью совпал.

В начале окна было 56 элементов baseline и 59 элементов trial. Совпали 18 из 24 профильных ID, 9 из 12 match lookup ID и 9 из 12 PBP ID; полных архивов было 8 против 11. Поэтому общий прирост по профилям и identity links отмечен вместе с изменением состава очереди. Для фиксированных match lookup ID успешных переходов не было; одна успешная связь в trial пришла от нового события.

Архивный импорт `9c041ab6-da57-4c82-802a-b23ac39f944e` использовал сохранённый checkpoint: число сохранённых страниц снизилось с 219 до 0, после чего импорт завершился. За окно завершились четыре задания полного архива. PBP-документы за интервалы не прибавились: по 33 в каждом окне.

## Здоровье и ограничения

Worker, Research, Backend и frontend оставались healthy на всех 102 срезах trial. Worker не перезапускался, OOM не было; cooldown не включался. Пиковая память worker составила около 1.86 GiB, а минимальная доступная память хоста в ручных проверках оставалась выше 2 GiB. Сетевой бюджет не менялся: два одновременных запроса, интервал старта 2 секунды и действующий cooldown.

Несмотря на рост успешных профилей и архивный прогресс, p95 live PBP ожидания вырос с 13 до 63 секунд при допустимом увеличении не более 10%. Поэтому после измерения worker возвращён к 2 browser slots, 1.5 CPU и 2 GiB RAM. Очередь всё ещё показывает ограничение данных: значительная часть match lookup и PBP задач ждёт подготовки игроков (`waiting_players`), а не свободных браузеров.
