- Измерительный скрипт пишет отдельную live PBP backlog-выборку с разбивкой статусов, возрастом ожидания и причиной. Изменения покрыты focused regression tests; исследовательская Docker suite: 92 passed, 2 warnings. После build/redeploy Research и Flashscore worker healthy.
- Повторный soak: [`flashscore_soak_2026-10-26_identity-routing.jsonl`](flashscore_soak_2026-10-26_identity-routing.jsonl), 81 точка за 30.45 минуты, все API ответы HTTP 200, worker healthy 81/81; latency p50/p95/max 0.208/0.391/0.618 с. `overdue_pbp` достигал 1, был ненулевым в 79/81 точках. Live backlog изменился с 11 (10 `waiting_players`, 1 `queued`) до 24 (22 `waiting_players`, 1 `queued`, 1 `waiting_match`); eligible-события 11→24. - Вывод: API, worker, поиск и запись документов работоспособны. Пункт 1424 закрыт по инструкции пользователя при недостаточном источниковом покрытии: stale-demand и bounded retry реализованы и проверены; устойчивое снижение на фиксированной когорте не доказано и не заявляется.

Это устраняет удержание профильных задач 140 stale live PBP jobs, не удаляя их историю. Отрицательный поиск для участника текущего live PBP повторяется не чаще раза в час; rejected/ambiguous identities по-прежнему требуют ручного решения. Runtime query подтвердила `stale demand=false`, `active demand=true`; focused suite — 50 passed. После rollout оба сервиса healthy; первый read-only срез показал 21 waiting_players из 23 live PBP jobs и overdue=1, поэтому снижение backlog ещё не подтверждено.
- Проверка действия retry: [`flashscore_soak_2026-10-26_stale-demand-fix.jsonl`](flashscore_soak_2026-10-26_stale-demand-fix.jsonl), 122 среза за 60.2 минуты, 122/122 HTTP 200, worker healthy 122/122, latency p50/p95/max 0.212/0.358/0.602 с. Вывод: stale-demand и backoff-механизмы проверены, пункт закрыт согласно пользовательскому правилу при недостатке данных; coverage gap и отсутствие доказанного fixed-cohort снижения остаются явно задокументированными ограничениями.
