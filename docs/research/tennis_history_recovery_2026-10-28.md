## Исправления сопоставления

- Для обычного завершённого гейма прежний код ошибочно требовал равенства его счёта финальному счёту всего сета. Теперь промежуточный результат проверяется по границам официального сета, а завершённый сет — на точное совпадение.
- Flashscore сохраняет в строках розыгрышей post-game score. Для привязки к Fonbet используется pre-game score только при наличии подтверждённого terminal game-result marker в той же версии. Неизвестный/конфликтующий результат не разрешает сдвигать счёт или подставлять следующий гейм.
- Привязка геймовой метки требует известного номера сета и счёта геймов. Полнота point-state и всего вектора признаков проверяется отдельно.
- Официальный Fonbet результат используется для сетовых меток независимо от публикации внешнего PBP. Метки прикрепляются к наблюдениям соответствующего сета до получения результата.
- JSONB истории загружается порциями до 50 версий по точным PK после отдельного чтения ключей. Прежняя общая выборка JSONB по source IDs достигала SQL-таймаута.

Сырые снимки, версии источников и исторические времена доступности не изменялись. Audit format 3 / `confirmed_pre_game_score_v1`; новый census использует checkpoint 6. Старые checkpoint-5 shards сохраняются как исторические данные и не могут смешиваться с новой схемой сопоставления.

На реальных проверенных документах без истории сохраняется `PBP_TAB_NOT_PUBLISHED`; успешный HTTP и найденная связь не считаются полученными розыгрышами.
